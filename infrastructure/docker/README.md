# Container release contract

All release images are built from the repository root so the Gradle multi-project build can resolve shared modules. Images must be tagged with the immutable source commit and pushed by CI; production manifests must reference the resulting tag or digest.

The Phase 3 service Dockerfiles live here for historical compatibility. Phase 4–7 Dockerfiles live beside their service. The release workflow maps both locations explicitly and rejects `latest` for staging/production promotion.

Required image properties:

- multi-stage build with no Gradle toolchain in the runtime image;
- non-root runtime user;
- no credentials copied into an image layer;
- SBOM and provenance attestation generated by CI;
- vulnerability scan before promotion;
- immutable registry tag/digest recorded in the release manifest.

Runtime container hardening is enforced again at the Kubernetes pod/container level because image configuration alone is not a sufficient policy boundary.
